## How it works

Paste your route file into the input. Invokix reads your route definitions, infers request and response shapes from your TypeScript types and Zod schemas, and produces a complete OpenAPI 3.0 contract. The result opens in the editor for review before you publish.

This works best when your routes have:
- TypeScript types on request bodies and responses
- Zod validation schemas — Invokix reads these directly
- Consistent HTTP status codes in your responses

## Example — Next.js App Router

<DocsCode lang="typescript" title="app/api/orders/route.ts">
{`import { NextRequest, NextResponse } from "next/server"
import { z } from "zod"
import { db } from "@/lib/db"
import { orders } from "@/lib/db/schema"
import { requireSession } from "@/lib/auth/session"

const CreateOrderSchema = z.object({
  price: z.number().positive(),
  lineItems: z.array(z.object({
    productId: z.string(),
    quantity: z.number().int().positive(),
    price: z.number().positive(),
  }))
})

// GET /api/orders — list user orders
export async function GET(req: NextRequest) {
  const session = await requireSession()
  if (!session) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  }

  const userOrders = await db.select().from(orders)
  return NextResponse.json(userOrders)
}

// POST /api/orders — create a new order
export async function POST(req: NextRequest) {
  const session = await requireSession()
  if (!session) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  }

  const body = await req.json()
  const parsed = CreateOrderSchema.safeParse(body)
  if (!parsed.success) {
    return NextResponse.json({ error: "Invalid body" }, { status: 400 })
  }

  const order = await db.insert(orders).values({
    ...parsed.data,
    userId: session.user.id,
    status: "pending",
  }).returning()

  return NextResponse.json(order[0], { status: 201 })
}`}
</DocsCode>

## Supported frameworks

- **Next.js** — App Router `route.ts` handlers and Pages Router API routes
- **Express** — `router.get()`, `router.post()`, `app.use()` patterns
- **Fastify** — route definitions with inline schema objects
- **Hono** — `app.get()`, `app.post()` with Zod validators
- **NestJS** — controller classes with `@Get()`, `@Post()` decorators

## Tips for better extraction

- **Use Zod** — if you validate request bodies with Zod, Invokix reads the schema directly and produces the most accurate types
- **Add TypeScript return types** — `Promise<Order>` gives the AI exact response shape information
- **Paste multiple routes at once** — paste the entire file, not just one handler
- **Include comments** — `// GET /orders — list user orders` helps the AI write better summaries

## Accuracy

Route code extraction handles most patterns well. Complex cases — database-inferred return types, deeply nested conditional responses, or dynamic schema builders — may need manual cleanup in the editor after extraction.

Once your contract is stable, consider switching to **OpenAPI import** and maintaining the spec directly. It gives you full control and produces higher Health Scores.
